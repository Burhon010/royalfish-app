# Royal Fish — сайт-каталог, корзина и админ-панель

Полноценный проект на Node.js: публичный каталог морепродуктов
(`royalfish.tj`) с корзиной и оформлением заказа, и защищённая
панель управления товарами и заказами (`royalfish.tj/admin`) для
владельца.

---

**Как это связано:** один Node-сервер отдаёт и сайт, и админку, и API,
и загруженные фото — из одного процесса, с одной базой данных.
Когда владелец что-то меняет в админке, это сразу пишется в базу,
и каталог на сайте при следующей загрузке страницы (или обновлении)
покажет новые данные — никакой отдельной синхронизации не нужно.

## 2. Запуск локально в VS Code

**Требования:** установленный [Node.js](https://nodejs.org) версии 18
или новее (проверить: `node -v` в терминале).

1. Откройте папку `royalfish-app` в VS Code: `File → Open Folder…`

2. Откройте встроенный терминал: `Terminal → New Terminal`

3. Создайте бесплатную базу Postgres — 2 минуты:
   - Зайдите на [neon.tech](https://neon.tech) (или
     [supabase.com](https://supabase.com)) и создайте бесплатный
     проект.
   - Скопируйте **Connection string** (строку подключения) —
     выглядит как `postgresql://user:password@host/dbname?sslmode=require`.

3a. Создайте бесплатный аккаунт для хранения фото — 1 минута:
   - Зайдите на [cloudinary.com](https://cloudinary.com) и
     зарегистрируйтесь (бесплатный тариф).
   - В **Dashboard** скопируйте **Cloud name**, **API Key** и
     **API Secret**.

4. Создайте файл окружения:
   ```
   cp .env.example .env
   ```
   (на Windows в PowerShell: `copy .env.example .env`)

5. Откройте `.env`, вставьте скопированную строку в `DATABASE_URL`,
   данные Cloudinary в `CLOUDINARY_*`, и задайте свои логин/пароль
   администратора и секретный ключ (см. раздел 4 ниже). Логин/пароль
   можно оставить по умолчанию для первого локального теста и
   сменить позже.

6. Установите зависимости:
   ```
   npm install
   ```

7. Запустите сервер:
   ```
   npm start
   ```
   Для разработки с автоперезапуском при изменении файлов:
   ```
   npm run dev
   ```

8. Откройте в браузере:
   - Сайт: **http://localhost:3000**
   - Админ-панель: **http://localhost:3000/admin**

При первом запуске сервер сам создаст таблицы в базе данных,
учётную запись администратора и 6 демо-товаров — ничего вручную
настраивать не нужно. Если сервер не стартует — первым делом
проверьте, что `DATABASE_URL` в `.env` скопирован правильно.

## 3. Какие файлы открывать и что где менять

| Что нужно изменить | Файл |
|---|---|
| Товары, цены, фото, скидки, наличие | **только через админ-панель** `/admin` — вручную в коде их лучше не трогать |
| Часы работы, адрес (тексты на сайте) | `public/index.html` — блоки `#contacts` и footer |
| Цвета, шрифты, отступы | `public/styles.css` (переменные вверху файла в `:root`) |
| Логотип | `public/assets/logo-circle-480.png` — просто замените файл тем же именем |
| Логин/пароль администратора по умолчанию, секретный ключ | `.env` |
| Список категорий товаров | `server/db.js` (CHECK-ограничение) + `public/index.html` и `public/admin/dashboard.html` (выпадающий список и фильтры) — потребуется правка в 3 местах, если категорию добавлять |

Владельцу магазина трогать код не нужно вообще — всё управление
товарами происходит через `/admin`.

## 4. Тестовый аккаунт администратора

Создаётся автоматически при первом запуске сервера из переменных
в `.env`:

```
ADMIN_USERNAME=admin
ADMIN_PASSWORD=change-this-password-now
```

**Для локального теста прямо сейчас**, если вы ничего не меняли в
`.env`, войдите на `http://localhost:3000/admin` с:

- **Логин:** `admin`
- **Пароль:** `change-this-password-now`

⚠️ **Это одноразовый пароль по умолчанию.** Сразу после первого
входа откройте кнопку **«Сменить пароль»** в шапке админ-панели и
задайте новый, надёжный пароль. Учётная запись создаётся в базе
данных только один раз — если поменять `ADMIN_USERNAME`/`ADMIN_PASSWORD`
в `.env` уже после первого запуска, это не изменит существующего
администратора (используйте «Сменить пароль» в интерфейсе).

Если нужно сбросить всё с нуля (например, для чистого теста):
зайдите в панель Neon/Supabase, откройте SQL-редактор и выполните
`DROP TABLE order_items, orders, admins, products;` — при следующем
запуске сервер создаст таблицы заново и засеет их настройками из
`.env`. Если нужно очистить только заказы, не трогая товары и
администратора: `DROP TABLE order_items, orders;`.

## 5. Проверка функциональности

Всё перечисленное ниже уже реализовано и связано между собой:

✅ **Добавление товара** — кнопка «+ Добавить товар» в админке →
заполняете форму → «Сохранить» → товар сразу появляется в списке
и в публичном каталоге.

✅ **Загрузка фото** — при добавлении/редактировании товара кнопка
«Загрузить / заменить фото» (JPG/PNG/WEBP, до 4 МБ), файл уходит
в Cloudinary, а ссылка на него пишется в базу данных.

✅ **Изменение цены** — поле «Цена, сомони» в форме редактирования;
сохраняется мгновенно.

✅ **Автоматический расчёт цены со скидкой** — поле «Скидка, %»
в форме сразу пересчитывает и показывает «Цена после скидки»
(JS на клиенте для предпросмотра + окончательный пересчёт на
сервере при сохранении — так цена не может быть подделана).

✅ **Статус «В наличии / Нет в наличии»** — переключатель прямо в
строке товара (без открытия формы) или выпадающий список внутри
формы редактирования — применяется мгновенно.

✅ **Изменения сразу видны в каталоге** — публичная страница
запрашивает актуальный список через `GET /api/products` при каждой
загрузке; отдельного шага «опубликовать» или пересборки сайта не
требуется.

**Как проверить руками за 2 минуты:**
1. Откройте `/admin`, войдите.
2. Нажмите «Добавить товар», заполните любые поля, загрузите фото,
   поставьте скидку 20% — увидите, что «Цена после скидки»
   пересчиталась сама. Сохраните.
3. Откройте сайт (`/` в новой вкладке) — новый товар уже в каталоге.
4. Вернитесь в админку, переключите тумблер «В наличии» у любого
   товара на «выкл» — обновите вкладку с сайтом — товар помечен
   «Нет в наличии».
5. Нажмите на карандаш (редактировать) у товара, замените фото —
   обновите сайт — фото уже новое.
6. Удалите товар (корзина) — на сайте он пропал.

## 5a. Заказы — как это работает

Покупатель добавляет товары в корзину (хранится в браузере,
`localStorage`) прямо на сайте, оформляет заказ через форму
(имя, телефон, необязательно адрес и комментарий). Сервер сам
проверяет каждый товар и пересчитывает сумму по актуальным ценам
из базы — цену из браузера сервер игнорирует, чтобы её нельзя было
подделать. Название и цена каждого товара сохраняются "снимком" на
момент заказа, поэтому история уже оформленных заказов не меняется
задним числом, даже если товар потом отредактируют или удалят.

Владелец видит все заказы в админке на отдельной странице
`/admin/orders.html` (ссылка «Заказы» в шапке рядом с товарами):
список с именем/телефоном клиента, составом, суммой и статусом,
фильтр по статусу, и подробности каждого заказа по клику. Статус
меняется прямо в списке или в деталях: **Новый → В обработке →
Доставляется → Завершён**.

**Как проверить руками:**
1. На сайте добавьте 1–2 товара в корзину (кнопка «В корзину» на
   карточке), откройте корзину (плавающая кнопка справа внизу).
2. Нажмите «Оформить заказ», заполните имя и телефон, подтвердите.
3. Увидите экран «Заказ №… принят».
4. В админке откройте «Заказы» — новый заказ должен быть в списке
   со статусом «Новый».
5. Смените статус на «В обработке» — он сразу обновится без
   перезагрузки страницы.
6. Откройте заказ по значку 👁 — проверьте, что состав и сумма
   совпадают с тем, что вы заказывали.

## 5b. Уведомления о заказах в Telegram

При каждом новом заказе владелец получает сообщение в Telegram с
полной информацией: номер заказа, дата, товары с количеством и
ценой, итоговая сумма, имя клиента, телефон, адрес, комментарий.

**Важно:** уведомление отправляется **после** того, как заказ уже
надёжно сохранён в базе данных, и не блокирует ответ покупателю.
Если Telegram временно недоступен или переменные не заданы —
заказ всё равно сохранится и будет виден в админке, просто без
уведомления. Ошибка отправки только записывается в логи сервера
(`[telegram] ...`), сайт при этом не ломается.

**Настройка (2 минуты):**
1. В Telegram напишите **@BotFather** → `/newbot` → задайте имя и
   username (должен заканчиваться на `bot`). Он пришлёт токен вида
   `123456789:AA...` — это `TELEGRAM_BOT_TOKEN`.
2. Напишите своему новому боту любое сообщение (например «привет»)
   — иначе он не сможет писать вам первым.
3. Узнайте свой `TELEGRAM_CHAT_ID` — напишите **@userinfobot**
   команду `/start`, он пришлёт ваш числовой ID.
4. Добавьте оба значения в `.env` (локально) и в **Vercel →
   Settings → Environment Variables** (на хостинге):
   ```
   TELEGRAM_BOT_TOKEN=...
   TELEGRAM_CHAT_ID=...
   ```
5. Перезапустите сервер (локально) или сделайте новый деплой (на
   Vercel переменные подхватятся автоматически при следующем
   запросе после сохранения).

**Как проверить:**
1. Оформите тестовый заказ на сайте.
2. В течение нескольких секунд в Telegram от вашего бота должно
   прийти сообщение с деталями заказа.
3. Если сообщение не пришло — проверьте логи сервера на строку
   `[telegram] ...` с описанием ошибки (обычно это опечатка в
   токене/chat_id или бот, которому вы не написали первое
   сообщение).

Хотите уведомления в общий чат с сотрудниками, а не только себе
лично — создайте Telegram-группу, добавьте туда бота, и используйте
ID этой группы как `TELEGRAM_CHAT_ID` вместо личного.

## 6. Безопасность и продакшен

Реализовано:
- Пароль администратора хранится в базе **только в виде bcrypt-хэша**,
  не в открытом виде.
- Сессия администратора — подписанный HMAC-токен в httpOnly-cookie
  (недоступен из JavaScript в браузере, защищён от подделки).
- Простая защита от перебора пароля (блокировка на 10 минут после
  8 неудачных попыток с одного IP).
- Проверка типа и размера загружаемых файлов (только изображения,
  до 4 МБ).
- Все админ-эндпойнты (`/api/admin/...`) требуют действующую сессию.

Перед реальным запуском на `royalfish.tj`:
1. Задайте надёжный `SESSION_SECRET` в `.env` (например,
   `openssl rand -hex 32`), и **обязательно смените пароль
   администратора** через интерфейс после первого входа.
2. Разместите сайт за HTTPS (например, через Nginx + Let's Encrypt/
   Certbot). Установите `NODE_ENV=production` в `.env` — тогда
   cookie сессии будет отправляться только по HTTPS (`secure`).
3. Используйте менеджер процессов (`pm2` или systemd-сервис), чтобы
   сервер перезапускался автоматически при сбое или перезагрузке.
4. Товары и администраторы хранятся во внешней базе Postgres, а
   не на диске сервера — задайте `DATABASE_URL` в переменных
   окружения хостинга (см. `.env.example`). Подходит бесплатный
   проект на [neon.tech](https://neon.tech) или
   [supabase.com](https://supabase.com). На бесплатном тарифе
   Render это обязательно: у него нет постоянного диска, и без
   внешней БД товары будут пропадать при каждом "засыпании"
   сервиса.
4a. Фото товаров, загружаемые через админку, хранятся в
   Cloudinary (бесплатный тариф) — задайте `CLOUDINARY_CLOUD_NAME`,
   `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` в переменных
   окружения (см. `.env.example`). Без них загрузка фото будет
   выдавать ошибку — сам товар при этом сохранится, просто без
   картинки.
5. Делайте регулярные бэкапы базы данных (в Neon/Supabase есть
   встроенные снапшоты).
6. Никогда не публикуйте файл `.env` (он уже в `.gitignore`).

## 6a. Деплой на Vercel

Проект настроен так, чтобы работать и на обычном хостинге (Render,
VPS — через `server/index.js`), и на Vercel (serverless — через
`api/index.js` + `vercel.json`). Логика приложения общая
(`server/app.js`), под Vercel её оборачивает отдельный вход.

**Важно понимать до деплоя:**
- Бесплатный тариф Vercel (Hobby) по условиям использования
  предназначен только для личных некоммерческих проектов. Royal
  Fish — работающий магазин, то есть формально для него нужен
  платный тариф **Pro** (от $20/мес). Часть небольших коммерческих
  сайтов месяцами работает на Hobby без проблем, но это нарушение
  правил площадки, а не поддерживаемый сценарий.
- Serverless-функции Vercel ограничены **10 секундами** выполнения
  на Hobby (60 сек на Pro) и **4.5 МБ** на весь запрос целиком —
  поэтому лимит фото уже понижен до 4 МБ (см. `admin-products.routes.js`).
- Каждый "холодный старт" функции — это новое подключение к базе
  данных. Если у вас Neon — используйте **pooled**-строку
  подключения (в Neon Dashboard она обычно содержит `-pooler` в
  адресе хоста) вместо прямой — иначе при активном использовании
  можно упереться в лимит одновременных подключений бесплатного
  тарифа.

**Шаги:**
1. Зарегистрируйтесь на [vercel.com](https://vercel.com) и
   подключите ваш GitHub-репозиторий с этим проектом (Import
   Project → выберите репозиторий).
2. Vercel определит проект автоматически (Node.js, без фреймворка) —
   ничего в настройках сборки менять не нужно.
3. В **Settings → Environment Variables** добавьте те же переменные,
   что и в `.env.example`: `DATABASE_URL` (лучше pooled-строку),
   `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`,
   `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `SESSION_SECRET`,
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
4. Нажмите **Deploy**. После сборки сайт будет на
   `https://ваш-проект.vercel.app`, админка — на `/admin`, ровно
   как на Render.
5. Проверьте функциональность по чек-листу из раздела 5 — особое
   внимание на загрузку фото (самое чувствительное место к лимитам
   Vercel).

## 7. На будущее

Структура уже готова к расширению:
- можно добавить второго администратора — просто вставить новую
  строку в таблицу `admins` (хэш пароля через `bcryptjs`);
- можно перейти на облачное хранилище фото (S3-совместимое) —
